Lifecycle REST

Step 1 — Create a battle REST

POST /battles — you become the creator and are auto-added as a player.

Step 2 — Pick a target battle

Every action below acts on this Battle ID. Auto-fills after you create one — or paste an id from a teammate to join theirs.

Battle state

Updates automatically after create / join / leave / start / any refresh.

No battle loaded yet — create one or paste a Battle ID and click "Refresh battle info".

Step 3 — Join / Leave WebSocket

Requires the WebSocket connected (Settings tab) and a valid session. Join puts you in the battle's player list and its live room. Leave only works while the battle is still WAITING.

Step 4 — Submit code WebSocket

Tests the gateway's submitCode handler. Join a battle first, then send code with a language and optional stdin.

The backend emits codeSubmitted, then codeResult or battle:playerWon into the battle room.

Step 4 — Start / Cancel

Start (WebSocket) — creator only, moves WAITING → RUNNING, broadcasts to everyone in the room. Cancel (REST) — creator only, only while WAITING.
